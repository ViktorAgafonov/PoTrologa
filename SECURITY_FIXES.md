# Исправления безопасности

Дата: 18.06.2026

## Критические уязвимости (исправлены)

### 1. Path Traversal (LFI) - скачивание бэкапов
**Файл:** `src/controllers/backupController.ts:31`

**Проблема:** Отсутствие валидации имени файла позволяло скачивать произвольные файлы системы через `../` в пути.

**Исправление:** Добавлена проверка `isSafeFilename()` перед формированием пути.

```typescript
if (!isSafeFilename(filename)) {
  res.status(400).json({ success: false, message: 'Некорректное имя файла' });
  return;
}
```

---

### 2. Path Traversal (LFI) - управление шаблонами
**Файлы:** `src/controllers/templateController.ts`, `src/services/templateService.ts`

**Проблема:** Несколько эндпоинтов позволяли читать/удалять/изменять произвольные файлы через манипуляцию с именем шаблона.

**Исправление:**
- Валидация `isSafeFilename()` во всех методах контроллера
- Санитизация `sanitizeFilename()` при загрузке файлов

---

### 3. Path Traversal (LFI) - загрузка документов
**Файл:** `src/services/documentService.ts:21`

**Проблема:** Параметр `customFilename` передавался без валидации, позволяя записывать файлы в произвольные директории.

**Исправление:** Все имена файлов проходят через `sanitizeFilename()`.

---

### 4. Path Traversal (LFI) - генерация актов списания
**Файл:** `src/controllers/writeoffController.ts:79`

**Проблема:** Имя шаблона из тела запроса использовалось без проверки.

**Исправление:** Добавлена валидация `isSafeFilename()`.

---

### 5. Хардкод пароля администратора
**Файл:** `src/app.ts:46`

**Проблема:** При первом запуске создавался пользователь `admin` с паролем `admin`.

**Исправление:** Генерация криптографически случайного 12-символьного пароля из набора `[A-Za-z0-9]` с исключением похожих символов. Пароль выводится в консоль при создании.

---

### 6. Дефолтный sessionSecret
**Файл:** `src/config/env.ts:9`

**Проблема:** При отсутствии `SESSION_SECRET` использовалось значение `potrologa-secret`, что позволяет подделывать сессии.

**Исправление:** Приложение не запускается без явно заданного `SESSION_SECRET` в `.env`.

```typescript
if (!sessionSecret) {
  throw new Error('SESSION_SECRET обязательно должен быть задан в .env файле');
}
```

---

## Прочие исправления

### 7. Автосинхронизация схемы БД (synchronize: true)
**Файл:** `src/config/database.ts:24`

**Проблема:** `synchronize: true` в TypeORM автоматически изменяет схему БД при старте, что опасно для продакшена.

**Исправление:** Добавлено предупреждение в лог при запуске в не-dev окружении.

---

### 8. Утечка информации через ошибки
**Файл:** `src/middleware/errorHandler.ts:6`

**Проблема:** Детали ошибок (stack trace, сообщения) отправлялись клиенту.

**Исправление:** В продакшене клиент получает только generic message `'Внутренняя ошибка сервера'`.

---

### 9. Race condition в генерации инвентарных номеров
**Файл:** `src/services/inventoryService.ts`

**Проблема:** При одновременных запросах возможно дублирование номеров (read-modify-write без блокировки).

**Исправление:** Использование транзакций с `pessimistic_write` блокировкой.

---

### 10. Утечка памяти в сессиях импорта
**Файл:** `src/services/importService.ts:54`

**Проблема:** Данные импорта хранились в `Map` без ограничения по времени.

**Исправление:** Добавлен TTL 30 минут, автоматическая очистка при создании новой сессии.

---

### 11. Отсутствие лимита на размер загружаемых файлов
**Файл:** `src/routes/index.ts:23`

**Проблема:** Multer не имел ограничения `fileSize`, что позволяло DoS-атаки через загрузку огромных файлов.

**Исправление:** Установлен лимит 50MB.

---

## Рекомендации после обновления

1. **Обязательно** задайте `SESSION_SECRET` в `.env` файле (минимум 32 символа)
2. При первом запуске скопируйте временный пароль admin из консоли
3. Для продакшена установите `NODE_ENV=production`
4. Рассмотрите использование миграций вместо `synchronize: true`
